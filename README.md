## OKX 轉 MAX 的基本流程

整個流程可以簡化成四個階段：

1. 在 MAX 找到要接收的幣種與充值網路。
2. 複製 MAX 顯示的充值地址，必要時記下 Memo 或 Tag。
3. 回到 OKX，選擇相同幣種與完全一致的提幣網路。
4. 先小額測試，確認入帳後再轉移剩餘資產。

MAX 官方說明指出，建立帳戶後平台會自動產生錢包地址。使用者需要進入 `Wallet`，選擇要接收的加密貨幣，再點選 `Deposit`，確認注意事項後複製地址。

這裡最重要的一句話是：**先在 MAX 取得收款資料，再到 OKX 提幣。**

不要先在 OKX 填一堆資料，最後才回頭找 MAX 地址。這種順序很容易漏掉網路或 Memo。

## 第一步：在 MAX 取得充值地址

登入 MAX 後，依序進入錢包或資產頁面，找到你想接收的幣種。

以 USDT 為例：

1. 開啟 MAX App 或網站。
2. 進入錢包、資產或充值頁面。
3. 搜尋並選擇 `USDT`。
4. 點選「充值」或 `Deposit`。
5. 查看 MAX 支援的網路。
6. 複製充值地址。
7. 如果頁面顯示 Memo、Tag 或其他識別欄位，也一併記下。

MAX 的官方說明特別提醒，區塊鏈地址有多種格式，使用前需要確認地址是否正確。某些幣種，例如 XRP，還可能要求填寫 Memo 或 Destination Tag；漏填或填錯，可能導致交易無法正常入帳。

### 為什麼不能直接使用以前保存的地址？

因為平台可能調整充值地址、支援網路或入金規則。即使你曾經成功把 USDT 轉到某個地址，也不代表下一次仍然可以照舊操作。

每次轉帳前，建議重新打開 MAX 的充值頁面，確認：

- 幣種名稱是否正確；
- 充值網路是否仍然支援；
- 是否有最低充值金額；
- 是否需要 Memo 或 Tag；
- 是否出現暫停充值或維護提示。

如果 MAX 顯示的是 USDT-TRC20 地址，OKX 端就必須選 TRON 網路。若 MAX 顯示的是 Ethereum 網路，OKX 端就不能改選 TRON 或 BSC。

## 第二步：在 OKX 選擇提幣

取得 MAX 收款地址後，登入 OKX，進入資產頁面。

網頁版通常可以依序選擇：

1. `Assets`
2. `Withdraw`
3. 選擇要提領的加密貨幣
4. 選擇鏈上提幣
5. 貼上 MAX 充值地址
6. 選擇與 MAX 相同的網路
7. 輸入提幣數量
8. 核對預估手續費與實際到帳數量
9. 完成電子郵件、簡訊、Authenticator 或其他安全驗證

OKX 官方目前將提幣分成鏈上提幣與內部轉帳兩種。鏈上提幣是把資產轉到其他交易所或錢包；內部轉帳則是轉給 OKX 平台內的其他使用者，兩者的操作方式和費用邏輯不同。從 OKX 轉到 MAX，應使用鏈上提幣。

在 OKX 的提幣頁面，通常需要確認以下欄位：

| 欄位 | 應該怎麼確認 |
| --- | --- |
| 幣種 | 必須和 MAX 充值頁面完全相同 |
| 地址 | 貼上 MAX 最新顯示的充值地址 |
| 網路 | OKX 與 MAX 必須選同一條鏈 |
| 金額 | 高於 MAX 最低入金額，也要高於 OKX 最低提幣額 |
| Memo / Tag | MAX 有要求時必須填寫 |
| 手續費 | 以 OKX 提幣頁面當下顯示為準 |
| 實際到帳 | 轉出數量扣除相關提幣費後的金額 |

OKX 官方也提醒，當同一種資產有多個可用網路時，使用者必須確認提幣網路與收款平台的充值網路一致，否則可能造成資產損失。

## USDT 轉 MAX，TRC20、ERC20、BSC 怎麼選？

這是最多人出錯的地方。

USDT 不是只有一種網路。常見選項包括：

- TRON，也常被標示為 TRC20；
- Ethereum，也常被標示為 ERC20；
- BNB Smart Chain，也常被標示為 BEP20；
- 其他平台可能還會支援不同公鏈或 Layer 2 網路。

你不需要先判斷哪條鏈「最好」，只需要確認 **MAX 充值頁面與 OKX 提幣頁面使用的是同一條鏈**。

例如：

| MAX 充值頁面 | OKX 提幣頁面 |
| --- | --- |
| USDT-TRC20 | USDT-TRC20 |
| USDT-ERC20 | USDT-ERC20 |
| USDT-BEP20 | USDT-BEP20 |

以下組合不要使用：

| MAX 充值網路 | OKX 提幣網路 | 結果 |
| --- | --- | --- |
| TRC20 | ERC20 | 網路不一致，存在資產遺失風險 |
| ERC20 | BSC | 網路不一致，不應提交 |
| BSC | TRC20 | 網路不一致，不應提交 |

地址開頭相似，也不能當作判斷依據。某些地址格式看起來很接近，但實際所屬網路不同。最可靠的確認方式是看兩邊的網路名稱，而不是只看地址長相。

### 手續費最低的網路就是最適合的嗎？

不一定。

OKX 顯示的提幣費會依資產、網路、平台設定與網路狀態變化。官方說明指出，提幣費會受到網路壅塞、營運成本和平台更新時間影響，頁面上顯示的費用才是當下應以為準的數字。

因此，不要看到 TRC20 費用較低，就直接選 TRC20。先確認 MAX 是否真的支援該網路，再比較費用。

## 第三步：先做小額測試

第一次從 OKX 轉到 MAX，建議先轉一筆小額測試。

測試金額需要同時符合：

- 高於 MAX 的最低充值門檻；
- 高於 OKX 的最低提幣額；
- 扣除提幣費後，仍然足夠讓 MAX 入帳；
- 即使發生延遲，也不會影響你的主要資金安排。

提交後，可以在 OKX 查看提幣紀錄和交易雜湊，也可以在 MAX 查看充值紀錄。OKX 的提幣頁面會顯示交易狀態與相關資訊；如果鏈上交易已成功，但 MAX 尚未入帳，通常需要把 TxID、幣種、數量、地址和提幣時間提供給收款平台客服。

MAX 官方目前說明，正常情況下，充值或提領相關的區塊鏈處理會依系統與網路狀況進行；若遇到人工審核、鏈上壅塞或熱錢包補充等情況，時間可能延長。

小額測試成功後，再轉移主要資產。這一步看起來多花幾分鐘，但比處理一筆錯誤鏈上轉帳省事得多。

## OKX 轉 MAX 會有哪些手續費？

這筆轉帳可能涉及兩個部分：

1. OKX 提幣手續費；
2. MAX 後續交易、提領或法幣出金費用。

### OKX 提幣費

OKX 不會對加密貨幣充值收取網路費，但從 OKX 提幣時，提幣方需要支付頁面上顯示的費用。官方說明也指出，提幣費通常是按照每筆交易收取，而不是單純按照金額比例計算。

實際費用請在最後確認頁查看，因為同一種幣在不同網路上的費用可能不同。

### MAX 加密貨幣充值費

MAX 的加密貨幣充值頁面需要以當下顯示的條件為準。從操作邏輯來看，轉帳時主要成本通常出現在發送平台，也就是 OKX 的提幣費；但仍然要查看 MAX 是否有最低充值金額、特殊資產規則或暫停充值提示。

### MAX 新台幣出金費

如果你的目標是把資產轉到 MAX 後賣成新台幣，再提領到銀行帳戶，目前 MAX 官方說明：

- 新台幣入金不收平台手續費；
- 新台幣出金一般為每筆新台幣 30 元；
- 綁定 Bankee 帳戶出金可免手續費；
- 新台幣最低出金金額為 100 元；
- MAX Token 不可用來折抵新台幣出金費。

這表示「OKX 轉 MAX」和「MAX 提領台幣」是兩個不同階段，不要把鏈上提幣費和銀行出金費混在一起計算。

## 轉帳前的安全檢查清單

提交 OKX 提幣前，可以按照下面清單逐項核對：

- [ ] MAX 選的是正確幣種。
- [ ] MAX 充值地址是剛剛重新產生或重新查看的地址。
- [ ] OKX 和 MAX 選的是同一條區塊鏈網路。
- [ ] MAX 沒有顯示該幣種暫停充值。
- [ ] 充值金額高於 MAX 最低入金額。

- [ ] 已開啟雙重驗證，且沒有透過陌生人提供的連結或聊天訊息操作。

加密貨幣提幣一旦送上區塊鏈，通常不能像銀行轉帳那樣直接撤回。MAX 官方也明確提醒，提領提交後無法取消，地址和網路必須在確認前仔細核對。

## 常見問題

### OKX 可以直接轉台幣到 MAX 嗎？

通常不能把這件事理解成一般銀行轉帳。OKX 轉 MAX 的常見方式是先提領加密貨幣到 MAX，再在 MAX 將資產交易成新台幣，最後提領到已驗證的銀行帳戶。

實際支援的法幣服務會依帳戶地區、身分驗證狀態與平台功能而變化。若你的目標是台幣出金，應先確認 MAX 的銀行綁定和新台幣出金資格。

### USDT-TRC20 和 USDT-ERC20 可以互轉嗎？

不能直接把它們當成同一條網路使用。兩者都是 USDT，但底層區塊鏈不同。MAX 收款頁面選哪一條鏈，OKX 提幣時就要選同一條鏈。

### 為什麼 OKX 顯示已完成，MAX 卻還沒入帳？

可能原因包括：

- 區塊鏈尚未完成足夠確認；
- MAX 仍在處理充值；
- 使用了錯誤網路；
- 未填寫 Memo 或 Tag；
- 入金金額低於最低門檻；
- MAX 正在進行人工審核或錢包維護。

先查看 OKX 的 TxID，確認交易是否真的已在鏈上成功。如果地址和網路都正確，但 MAX 仍未入帳，將 TxID 和交易資料交給 MAX 客服查詢。

### 可以一次把全部資產轉過去嗎？

技術上可能可以，但第一次操作不建議這樣做。先用符合最低門檻的小額測試，確認 MAX 成功入帳，再轉移剩餘資產。這個步驟不能保證零風險，但可以降低地址、網路或 Memo 填寫錯誤造成的損失範圍。
